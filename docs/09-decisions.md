# 9. Decisions

A log of technical decisions. Add new ones at the bottom; don't delete old ones — mark them **Superseded** and link to the replacement.

| # | Decision | Status | Why |
|---|---|---|---|
| D1 | **Next.js 16 App Router** for UI and API | Decided | One codebase for pages, API routes and server actions. Note: Next 16 has breaking changes vs older tutorials — check `node_modules/next/dist/docs/` |
| D2 | **NextAuth v4 with JWT sessions**; GitHub sign-in (Google configured but no keys yet) | Decided | Came with the starter. Users are upserted into `users` on sign-in. Auth config lives in `lib/auth.ts` because route files may only export HTTP handlers |
| D3 | **Neon Postgres + Drizzle ORM** | Decided | Serverless Postgres, typed queries. Separate Neon project from the user's other apps |
| D4 | ~~**Google Gemini** (`@google/genai`) for agents, via the Gemini Developer API with an AI Studio key~~ | Superseded by D26 | Dropped after one day in use: on the free tier the full `flash` models all returned 503 and Google Search grounding had no quota at all, so neither the model nor the search tool we had designed around was actually reachable |
| D5 | **Inngest** for schedules, events and long-running runs | Decided | Already in the project; durable steps, retries, cron, wait-for-event (needed for approvals) |
| D6 | **DiceBear `clay` avatars** stored as a seed per agent | Decided | No image storage needed; same seed always gives the same avatar |
| D7 | ~~**Chat streams plain text** from the API route~~; only the model's own words are saved to history (error notes are not) | Stream format superseded by D23; the history rule still stands | Keeps history clean for the model |
| D8 | `drizzle-kit push` during early development | Decided (temporary) | Fast iteration. Replace with generated migrations before launch (see [data model](03-data-model.md#migrations)) |
| D9 | **One agent runner** shared by chat and background tasks | Decided, built (`lib/agent/runner.ts`) | Same behaviour everywhere; one place for limits and logging |
| D10 | **Approval required by default** for write/destructive tools | Proposed | Main defence against prompt injection ([security](07-security.md)) |
| D11 | ~~Hybrid integrations: Gmail in-house, integration platform for breadth, MCP later~~ | Superseded by D17 | — |
| D12 | **Sandbox provider** for per-agent VMs; agent loop stays on our server, only sandbox tools run in the VM | Decided (provider: D15) | Avoid running our own VM fleet; keep secrets out of VMs ([VMs](06-virtual-machines.md)) |
| D13 | **Encrypt OAuth tokens** at rest (AES-256-GCM, key from env → KMS later) | Decided, built (`lib/crypto.ts`) | Tokens grant full access to users' accounts, so the database alone must not be enough to read one. Ciphertexts are bound to their owner and provider as AAD, which also stops a token blob being moved between rows, and carry a `v1:` prefix so the algorithm can change later |
| D14 | **Individual users only** — agents and connections belong to a user; no team workspaces | Decided | Simpler data model and permissions. Teams can come later with a migration |
| D15 | **E2B** for per-agent sandboxes (dedicated VM feature) | Decided | Built for AI agents; fast start, pause/resume with persistent disk, TypeScript SDK |
| D16 | **Vercel** for hosting | Decided | Natural fit for Next.js; works with Inngest. Consequence: no long-running processes in our functions — background work goes through Inngest, local (stdio) MCP servers run inside E2B, not on Vercel |
| D17 | **MCP-first integrations**: Gmail built in-house; other apps via allow-listed **remote MCP servers** with per-user OAuth; fallback (own code or an integration platform) only for apps without a good MCP server | Proposed | Open standard, many official remote servers, one client in our runner covers many apps ([integrations](05-integrations.md)). Verify Slack/Notion/Jira servers at the start of Phase 5 |
| D18 | **Sign in with GitHub *and* Google** | Decided | Most non-developer users expect Google; both providers are already wired in `lib/auth.ts` and shown on the sign-in page. Needs `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`. Separate from the Gmail *connection* OAuth in Phase 3 ([integrations](05-integrations.md)) |
| D19 | **Markdown replies** with `react-markdown` + `remark-gfm`; only a fixed set of tags is rendered, no raw HTML; fenced code uses the existing `shiki` code block | Decided | Agents answer with lists, tables and code. Allowing raw HTML in model output would be an injection risk ([security](07-security.md)), and the shiki setup already highlights code as it streams |
| D20 | **One conversation per URL**: `/workspace/agent/:id?c=<conversation id>`; no `c` opens the most recent chat | Decided | Chats are shareable and survive a refresh. A brand-new chat updates the URL with `history.replaceState` so the reply keeps streaming |
| D21 | **Agent editing lives on its own page** (`agent/[id]/settings`) rather than in a dialog | Decided | Room for the per-agent Tools (Phase 3) and Tasks (Phase 4) settings to come |
| D22 | ~~**`web.search` is Gemini's own Google Search grounding**~~ | Superseded by D27 | The idea survives — search runs provider-side and we log it — only the provider changed |
| D23 | **Chat streams newline-delimited JSON events** (`text`, `activity`, `note`) instead of plain text | Decided | A turn is no longer only words: the UI has to show which tools ran while they run. One JSON object per line keeps it readable and needs no SSE framing. Supersedes the stream format in D7; `lib/agent/events.ts` holds the types for both sides |
| D24 | **Tool activity is shown live but not saved**; reopening a past chat shows the reply alone | Decided | The reply is the lasting artefact; the steps live in `run_steps` and will get a proper timeline in the Runs tab (Phase 4) rather than being replayed inline |
| D25 | **A native tool that the provider refuses is dropped, not fatal**: a refusal retries the turn without native tools. A **capability** refusal (400/403/404) blocks native tools for every later run on that server instance; a **rate limit** (429) drops them for the current run only. 402 (out of credits) is not handled this way | Decided | Found on the first live test: the free tier has no Google Search grounding quota, and because grounding travels in the same request as our function declarations, the refusal killed every message — including ones that only needed `time.now`. An optional tool being unavailable must not take the agent down with it. A capability block lasts **until the server instance restarts** — upgrading the account does not lift it on its own. The user is told only in the run where the refusal happened; later runs simply answer without search and say nothing |
| D26 | **OpenRouter** as the model provider, called with the **OpenAI SDK** (`openai`) pointed at `https://openrouter.ai/api/v1`; default model `deepseek/deepseek-chat-v3.1` | Decided | Replaces D4. One key reaches 478 models (415 with tool calling), so a model that is unavailable, too slow or too expensive is a one-line change in `lib/ai.ts` rather than a rewrite — the exact problem that killed D4. OpenRouter is wire-compatible with the OpenAI API, so the official SDK is the client and `@google/genai` is gone. DeepSeek v3.1 is $0.25/$0.95 per 1M tokens, about a third of Gemini 3.8 Flash's price on the same platform |
| D27 | **`web.search` is OpenRouter's `openrouter:web_search` server tool** | Decided | Replaces D22 and keeps its shape: the model decides when to search, OpenRouter runs it mid-request and feeds the results back, and we log what it cited. Two improvements over grounding — it works with **any** tool-calling model, so it survives a change of `CHAT_MODEL`, and it is declared per request rather than being a property of the model. Billed per search on top of tokens. We learn what it did from `url_citation` annotations and `usage.server_tool_use_details`, which is less than Gemini gave us (no query text), so the chat shows the hosts cited instead of the queries run |
| D28 | **Our own `web.fetch` is kept** rather than OpenRouter's `openrouter:web_fetch` server tool | Decided | It is already built, tested and free, it keeps the SSRF guard on our side ([security](07-security.md#fetching-urls-the-model-chose)), and the fetched text lands in our own `run_steps`. OpenRouter's version is the better choice later if JS-heavy pages or PDFs start mattering |
| D29 | **`write` tools may have approval turned off per tool; `destructive` may not** | Decided | Answers the open question that gated Phase 3. Approval-by-default is the main defence against prompt injection (D10), but requiring a click for every draft an agent writes would make it unusable — so a user can trust a specific `write` tool on a specific agent. `destructive` stays locked whatever the setting, because the blast radius is permanent and an agent reading strangers' email is exactly what an attacker aims at. `gmail.send` is `write`, so it *can* be trusted deliberately; a future delete tool could not |
| D30 | **One turn at a time per conversation**, enforced with a lease column `conversations.busy_until`: a turn claims the conversation with one conditional `UPDATE` (free, or lease expired) before saving the user's message, and releases it when the turn ends — success, failure or cancellation. A second message meanwhile gets **409** | Decided | Two overlapping messages (two tabs, a double send) would each generate from history missing the other's turn. There was no existing lock to reuse; a Postgres advisory lock would have to be held across the whole streamed reply, which doesn't hold up through Neon's pooled connections. The 10-minute expiry only matters if a server dies mid-turn |
| D31 | **`web.fetch` connects only to addresses it has checked**: requests go through an `undici` Agent whose DNS `lookup` refuses private addresses, so the check and the connection use the same answer | Decided | Checking the hostname and then letting `fetch` resolve it again left a window for DNS rebinding. `undici` was already installed (through `openai`) and is now a direct dependency |
| D32 | **Default model is `nvidia/nemotron-3-ultra-550b-a55b:free` while testing** (was `deepseek/deepseek-chat-v3.1`, D26) | Decided (temporary) | Lets the agent be tested with no credit on the account. `google/gemma-4-31b-it:free` was tried first, but its free provider answered 429 on every request (19 Nov 2026); Nemotron Ultra called the `time_now` tool correctly in about a second at $0. It is one of 15 free OpenRouter models with tool calling. Trade-offs: tight rate limits (one agent turn can use several requests), free providers may log prompts, and multi-step tool use is unproven on it. `web.search` is still billed per search, so it needs credit even with a free model. Switch back to a paid model before agents read real email (Phase 3) |
